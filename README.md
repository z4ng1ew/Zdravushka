# Здравушка — голосовой ассистент регистратуры поликлиники

Кейс DBI, хакатон «Точка сборки» 2026, команда 049.

Здравушка отвечает на звонки в регистратуру вместо оператора:
записывает к врачу, переносит и отменяет записи, подсказывает, когда принимает врач,
отвечает на справочные вопросы, принимает вызов врача на дом и обзванивает пациентов
с напоминаниями. Всё, что выходит за рамки регистратуры (угроза жизни, медицинские
вопросы, жалобы, просьба позвать человека), она передаёт сотрудникам по регламенту РГ-ТЕЛ-01
и создаёт заявку в МИС.

- Демо: https://tochka-sborki-2026-team-049.hub.gigaschool.ru
- Кабинет сотрудника: `/staff`
- API (Swagger): `/docs`
- Состояние сервиса: `/api/health`

## Зачем это поликлинике

Цифры взяты из выгрузок поликлиники: журнал звонков за 01.06–31.08.2026 (17 772 звонка)
и история записей за 25.03–24.09.2026 (35 470 записей).

| Проблема | Сейчас | Что даёт Здравушка |
|---|---|---|
| Пропущенные звонки | 20,7 %, а в 7:00 и 20:00–21:00 не отвечает никто | принимает звонки круглосуточно и без очереди |
| Неявки на приём | 11,5 % | напоминает о приёме и даёт сразу отменить или перенести запись, так что освободившийся слот уходит другому пациенту |
| Нагрузка на регистраторов | около 193 звонков в день | типовые звонки (запись, перенос, справка) закрываются без оператора |

## Как это устроено

```
 Linphone ⇄ SIP-шлюз хакатона           Сайт (демо, кабинет сотрудника)
        │  (входящие и напоминания)                   │
    Asterisk ⇄ AudioSocket :9092 ──┐                  │ HTTP
                                    ▼                 ▼
                       ┌──────────────────────────────────────┐
                       │          FastAPI  (app/main.py)      │
                       │                                      │
   речь → текст ◄──────┤ telephony.py: детектор речи,         │
   Whisper (шлюз)      │   перебивание, тишина                │
                       │ dialog.py: сценарии регламента       ├──► стенд «Регистратура» (МИС)
   понимание ◄─────────┤ nlu.py: LLM → JSON → проверка кодом  │     /doctors /clients
   GigaChat (шлюз)     │ safety.py: красные флаги, R-01…R-15  │     /visits /escalations
                       │ schedule.py: свободные слоты, ПГГ    │
   текст → речь ◄──────┤ tts.py: Piper локально               │
                       └──────────────────────────────────────┘
```

Главный принцип: **нейросеть только понимает речь, а решения принимает код.**
LLM переводит фразу пациента в JSON (намерение, специальность, ФИО, дата),
после чего код проверяет каждое поле:
- специальность ищется только в реальном справочнике;
- дата рождения должна быть настоящей и в прошлом;
- номер варианта может быть только от 1 до 3.

Поэтому модель не может «придумать» врача или время. Если LLM недоступна,
работает запасной разбор по ключевым словам, и звонок продолжается.

## Ресурсы и выбор моделей

VM: 4 vCPU, 8 ГБ памяти; вместе с Asterisk вся машина в работе загружена примерно на 8 % памяти и почти не нагружает процессор. Всё тяжёлое вынесено в шлюз нейросетей организаторов
(российский контур), а на VM работает только лёгкая логика.

| Задача | Модель | Почему |
|---|---|---|
| Понимание речи | `ai-sage/GigaChat3-10B-A1.8B` | отечественная; MoE-модель, в которой активны только 1,8 млрд параметров, поэтому быстрая и дешёвая (≈12 ₽ за 1 млн токенов, дневного лимита хватает на тысячи реплик) |
| Распознавание | `openai/whisper-large-v3` (шлюз) | высокое качество русского языка, бесплатно в шлюзе |
| Синтез речи | Piper `ru_RU-irina-medium` | работает на CPU прямо на VM, без сети, около 60 МБ |

Чтобы сократить задержку и расход:
- речь синтезируется по предложениям, и первое предложение звучит, пока готовится остальное;
- справочник врачей кэшируется;
- занятые слоты загружаются одним запросом на поиск;
- обращения к стенду держатся в пределах лимита 9 запросов в минуту.

**Если что-то отказало:**
- LLM недоступна → разбор по ключевым словам;
- внешний TTS не отвечает → Piper;
- стенд не отвечает больше 5 секунд → правило R-06, пациента вежливо переводят на сотрудника, звонок не обрывается.

## Регламент и пограничные случаи

| Ситуация | Поведение |
|---|---|
| Боль в груди или в сердце, удушье, потеря сознания и т. п. | сразу 103/112 (красный флаг категории А), заявка в МИС с наивысшим приоритетом, даже посреди записи или во время звонка-напоминания |
| Внезапная сильная головная боль («резко очень сильно заболела голова») | категория А (возможный инсульт): 103/112 и перевод |
| Сильная боль своими словами («очень сильно болит живот», «невыносимо») | срочный перевод на сотрудника (R-11) |
| Пациент не назвался, но нужна заявка | заявка на технического клиента «Срочный Вызов Иванович», как согласовано с организаторами |
| «Позовите человека», жалоба | перевод на сотрудника и заявка с кратким пересказом разговора |
| Медицинский вопрос («что выпить?») | вежливый отказ; если вопрос повторяется — перевод (R-04) |
| Три непонимания подряд | перевод на сотрудника (R-05) |
| Пожилой пациент плохо слышит | повтор громче и медленнее; если снова не слышит — перевод (R-15) |
| Тишина в трубке | через 5 секунд «Вы меня слышите?», ещё через 5 — вежливое завершение |
| Пациент перебивает | Здравушка замолкает и слушает |
| Повторный пациент | ищется по ФИО и дате рождения, дубль в МИС не создаётся |
| ФИО «услышано» в случайной фразе | ФИО принимается только в ответ на вопрос о нём, чтобы запись не ушла на чужое имя |
| Назвали только год рождения | подсказка: «число, месяц и год» |
| «Запишите к Дорохову», «перенесите к другому врачу» | учитывается врач по фамилии; к другому врачу — новая запись, старая отменяется после «да» |
| Назван день вместо номера варианта | новый поиск на этот день, а не выбор варианта |
| «Отмените обе» | отменяются все предложенные записи сразу |
| Whisper «слышит» в тишине «Продолжение следует…» | такие фразы-галлюцинации отбрасываются |
| Попытка двойной записи | слот считается свободным, только если он свободен по расписанию и в МИС нет записи на это время |
| Вызов врача на дом | заявка в МИС с адресом и поводом; ребёнку назначается педиатр |
| Сроки | запись к участковому в течение 24 часов, к узкому специалисту в течение 14 рабочих дней (ПГГ) |

Ещё несколько правил из регламента:
- Здравушка представляется виртуальным помощником;
- предлагает не больше трёх вариантов;
- называет даты с днём недели, а время — словами.

## Запуск

**На VM хакатона** (токены уже лежат в `/opt/hackathon/ai.env`):

```bash
./run.sh
```

Скрипт создаёт виртуальное окружение, ставит зависимости, скачивает голос Piper и
запускает сервер на `0.0.0.0:8000`. Проверка: `curl -s 127.0.0.1:8000/api/health` →
`"mode": "stand"`.

**Локально, без токена стенда** — с имитацией МИС в памяти (`app/mock_stand.py`):

```bash
STAND_MODE=mock TELEPHONY_ENABLED=0 ./run.sh
```

Имитация повторяет адреса, коды ответов и ошибки настоящего стенда, а ассистент работает
через тот же клиент `StandClient` — логика не меняется. В `/api/health` режим виден как `"mock"`.
Если нет ни токена, ни `STAND_MODE=mock`, ассистент **не выдумывает записи**, а переводит
пациента на регистратора (R-06), и `/api/health` показывает `"mode": "no-stand"`.

Настройки берутся из переменных окружения: см. `.env.example`.
На VM организаторов ключи читаются автоматически из `/opt/hackathon/ai.env`
(`DBI_API_TOKEN`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`). Секреты в репозиторий не попадают.

Проверка окружения:

```bash
python -m scripts.check_stand    # связь со стендом и справочник врачей
python -m scripts.check_models   # LLM, TTS и STT отвечают
```

## Тесты

```bash
pip install pytest pytest-asyncio
python -m pytest -q tests/
```

40 тестов на имитации стенда (настоящий МИС и лимит запросов не тратятся):
- запись, перенос, отмена, статус, отказ на подтверждении;
- повторный пациент без дубля, запрет двойной записи, «отмените обе»;
- врач по фамилии, перенос к другому врачу, день вместо номера варианта;
- экстренный случай до и посреди записи, боль в сердце, внезапная головная боль, сильная боль;
- оператор, жалоба, медицинский вопрос, «не слышу» дважды, три непонимания подряд;
- отказ МИС, галлюцинации Whisper, «какие есть врачи», неполная дата рождения;
- вызов на дом взрослому и ребёнку (в воскресенье эти два теста пропускаются: заявки не принимаются);
- звонок-напоминание: подтвердил, отменил, перенёс, экстренный случай во время напоминания;
- надёжность: нет МИС → перевод, а не выдуманная запись; LLM вернула мусор → запасной разбор;
  таймаут распознавания; сбой диска при записи журнала; сквозной сценарий через адаптер `mock`;
- ограничения кейса: недоверенный адрес нейросети отклоняется (152-ФЗ), ФИО скрыто в расшифровке,
  справочные ответы — только из регламента.

Большинство случаев взяты из живых звонков на стенде: каждая найденная ошибка закрыта тестом.

## Защита от выдумывания, сбоев и 152-ФЗ

**Ассистент не выдумывает.**
- Записи, врачи и время — только из МИС и расписания поликлиники. LLM лишь переводит фразу
  в JSON, и каждое поле проверяется кодом (специальность из справочника, реальная дата, вариант 1–3).
- Справочные ответы (адрес, часы, анализы, цены) берутся дословно из регламента РГ-ТЕЛ-01.
  Вопрос вне базы знаний → перевод на регистратора (R-08), а не ответ «от себя».
- Медицинских советов нет: симптомы → вежливый отказ, повтор → перевод (R-04), красные флаги → 103/112.
- Каждый ответ `/api/chat` помечен: `status` (`in_progress` / `completed` / `handoff` / `error`)
  и `source` (`МИС`, `регламент РГ-ТЕЛ-01`) — видно, откуда взят результат.

**Сбои не роняют звонок.**
| Что сломалось | Что происходит |
|---|---|
| LLM: таймаут, ошибка, пустой или битый ответ | ответ проверяется по формату → запасной разбор по ключевым словам |
| Распознавание: таймаут, 502 | «Не расслышала, повторите» |
| Whisper «услышал» тишину («Продолжение следует…») | фраза отбрасывается |
| МИС: 429, 5xx, таймаут > 5 с, неверный ответ | перевод на регистратора (R-06), заявка в журнале |
| Ошибка логики во время звонка | «Произошёл сбой, соединяю с регистратором» вместо тишины |
| Диск при записи журнала | журнал пишется атомарно; ошибка логируется, звонок продолжается |

**152-ФЗ.**
- Речь и текст пациента уходят только в доверенный контур: шлюз нейросетей хакатона
  (российский) или сервер в частной сети. Любой другой адрес LLM/STT/TTS отключается при
  старте (`TRUSTED_AI_HOSTS`), `/api/health` показывает `pd_trusted_ai_only`.
- Синтез речи — Piper локально на VM, текст никуда не уходит.
- В журнале звонков ФИО маскируется («Иванов И. И.»), а реплики с ФИО и датой рождения
  в расшифровке заменяются на «[скрыто]»: персональные данные хранятся только в МИС.
- Ассистент в начале звонка предупреждает о записи разговора.
- Токены — только в переменных окружения, не в репозитории.

## Телефония

Звонки идут через SIP-шлюз хакатона, публичный IP и свой провайдер не нужны.
Asterisk на VM зарегистрирован в шлюзе (учётка `vm-049`), пациент звонит с софтфона Linphone
(учётка `phone-049`) на номер **049**. Звук — G.711 (8 кГц), Asterisk сам переводит его в slin для AudioSocket.

**Входящий звонок:**
```
Linphone → шлюз → Asterisk [from-gateway] → AudioSocket(UUID, 127.0.0.1:9092) → Здравушка
```
Здравушка распознаёт конец фразы по паузе, позволяет себя перебить, при тишине спрашивает
«Вы меня слышите?» и всё время держит в трубке непрерывный поток звука (кадры по 20 мс).

**Звонок-напоминание (за день до визита, сценарий С-10):**
1. Сотрудник нажимает «Обзвонить» (`POST /api/reminders/run`) или звонит по одной записи
   (`POST /api/reminders/{visit_id}/call`). Берутся записи на следующий рабочий день из МИС.
2. Здравушка придумывает UUID звонка и отдаёт Asterisk команду
   `channel originate PJSIP/phone-049@gateway application AudioSocket <UUID>,127.0.0.1:9092`.
3. Пациент берёт трубку → Asterisk подключается к Здравушке с этим UUID, и она знает, о какой записи говорить:
   «Напоминаю о записи: терапевт, врач …, завтра в девять ноль-ноль, кабинет 106. Вы придёте?»
4. Результат сразу фиксируется в МИС и на экране «Напоминания»:

| Ответ | МИС | Статус |
|---|---|---|
| «Да» | комментарий «Подтвердил визит» в карточке пациента | подтвердил |
| «Нет» → «отмените» | запись отменена, слот свободен | отменил |
| «Перенесите» | 3 варианта у того же врача → перенос | перенёс (+ новое время) |
| Не взяли трубку за 60 с | без изменений | не дозвонились (повтор при следующем обзвоне) |

Звонки идут по очереди: один разговор за раз.

Диалплан — `telephony/asterisk/extensions.conf` (учётки и пароли SIP в репозиторий не кладём,
они в `/opt/hackathon/sip/`). Для отладки без телефона есть `scripts/phone_sim.py`:
он говорит с ассистентом через микрофон по тому же протоколу AudioSocket.
