# Регистратура+ — фронтенд голосового ассистента

Экран звонка пациента, кабинет регистратуры (очередь переводов, обзвон, журнал звонков, расписание, статистика) без кабинета врача (по кейсу его рабочее место — МИС).
Next.js 15 + TypeScript, обычный CSS, без сторонних UI-библиотек, внешних CDN и аналитики.

## Как сдать в репозиторий бэкенда

1. Исходники фронта — в папку `frontend/` репозитория (без `node_modules`, `.next`, `out`).
2. Собрать и положить сборку в `static/` (заменяет её целиком):
   ```bash
   cd frontend
   npm ci
   npm run check         # типы, линтер, тесты
   npm run export          # = next build + копирование out/ → ../static
   ```
3. Перезапустить сервер и проверить: открыть сайт, пройти запись — под ответом зелёный бейдж «✓ Записано в МИС · № записи …».

## Запуск

```bash
npm install
npm run dev          # http://localhost:3000 — разработка
```

### Вместе с бэкендом Здравушки (всё на порту 8000)

Бэкенд — репозиторий Zdravushka (Мовсар). FastAPI отдаёт фронт из папки `static/`.

```bash
npm run export -- ../Zdravushka/static   # собрать и скопировать в static/ бэкенда
cd ../Zdravushka && uvicorn app.main:app --reload --port 8000
```
Открыть http://localhost:8000/ — экран пациента, http://localhost:8000/staff/ — кабинет.
После каждой пересборки фронта перезапустите uvicorn.

### Разработка фронта с живым бэкендом

Создайте `.env.local`:
```
NEXT_PUBLIC_API_URL=http://localhost:8000
```
и запустите `npm run dev`.

### Работа только с бэкендом

Демо-сценариев и примерных данных больше нет: экран пациента разговаривает только через `POST /api/chat`,
кабинет берёт данные только из API. При открытии экран проверяет `GET /api/health` —
под кнопками видно «● Сервер на связи» или «● Сервер недоступен».

### Ошибки

- **В чате** ошибка показывается одной крупной цифрой (400, 403, 404, 500…), расшифровка — при наведении.
  Нет связи с сервером — «—». На страницах кабинета — та же цифра вместо таблицы.
- **Журнал ошибок** — вкладка «Ошибки» в кабинете (`/staff/errors`): время, код, запрос, где, описание.
  Кнопка «Скачать .log» сохраняет файл — его можно отправить Мовсару. Журнал хранится в браузере (до 500 записей).
- Код — `shared/api/http.ts` (все запросы идут через `request()`), журнал — `shared/api/errorLog.ts`, вид — `shared/ui/ErrorCode.tsx`.

Что берём из ответа `/api/chat` (`shared/api/chat.ts`, формат — `app/models.py` бэкенда):

| Поле | Где на экране |
|---|---|
| `reply` | синяя реплика Здравушки |
| `intent` | «Намерение» в блоке «Что понял Здравушка» |
| `collected` | пункты с галочками там же |
| `options` | кнопки-варианты времени, по клику уходит `"1"`/`"2"`/`"3"` |
| `booking` | карточка записи: `status` пустой — «Ожидает подтверждения», «Запланирована» — «Записано в МИС» |
| `escalation` | перевод на регистратора; `emergency: true` — красный блок «Звоните 103 или 112» |
| `done` | звонок завершён (при переводе — ждём регистратора, не обрываем) |

Журнал звонков, очередь оператора и напоминания ждут эндпоинтов `/api/calls`, `/api/handoffs`, `/api/reminders` — пока бэкенд отвечает 404, и это видно цифрой.

## Два пользователя

Переключение — «плашка пользователя» в правом верхнем углу.

**Пациент** — `/` звонок Здравушке, `/tickets/` «Мои талоны».
После записи в чате сразу появляется **талон** — квитанция по настоящей записи в МИС: «Талон к записи № 93»
(номер — `booking.visit_id` из ответа сервера, фронт номера не придумывает; без номера записи талон не выдаётся),
врач, кабинет, дата и время. При переносе номер меняется на номер новой записи. Талоны можно распечатать;
на странице «Мои талоны» — поиск по врачу, дате и номеру записи. В браузере хранится только «Фамилия И. О.», без даты рождения; талоны старше 30 дней удаляются.
Под ответом Здравушки — бейдж (status/source) и мелким текстом понятное пояснение `explanation`.
Служебное — «понято нейросетью / по правилам» (`understood_by`) и «распознано на 87 %» (`asr_confidence`) —
видит только регистратор (расшифровки в кабинете, «Звонок сейчас»); пациенту оно не показывается.
При голосовом вводе точность из `/api/asr` уходит в `/api/chat` полем `asr_confidence` — при плохом распознавании бот переспрашивает.

Голос: на время озвучки микрофон выключен, после неё — пауза 0,4 с (затихает эхо), потом снова слушаем;
микрофон с `echoCancellation` и `noiseSuppression`. Первые 0,3 с записи не слушаем (замер фона), речью считаем
громкий звук не короче 0,3 с. «Не расслышал» — только если пациент говорил не меньше 0,7 с, а распознавание вернуло пусто;
короткий звук (щелчок, эхо) — как тишина, без подсказки.

Здравушка над микрофоном меняет настроение по ходу звонка (`features/call/model/mascot.ts`): ждёт → думает
(ждём ответ/распознаём) → «готово» (талон выдан, передано регистратору) или «сбой». Внутри лент разговора
и талонов всплывающих подсказок нет — их обрезала прокрутка; пояснения там обычным текстом.

**Журнал звонков**: отметка «⚠️ попытка промпт-инъекции» по полю `flags` звонка (`prompt_injection`), фильтр «С отметками».

**Регистратор** — `/staff/` (меню слева, раскрывается при наведении):

| Раздел | Что показывает |
|---|---|
| Регистратура `/staff/` | Показатели дня, очередь переводов, исходящий обзвон, журнал звонков с запросами к МИС |
| Ошибки `/staff/errors/` | Сбои МИС в звонках (с сервера) и ошибки запросов браузера с выгрузкой в .log |
| Звонок сейчас `/staff/live/` | Телефонные звонки, которые идут сейчас: расшифровка по ходу разговора и запросы к МИС. Ниже — демо-звонок из этого браузера, его можно перехватить |
| Расписание `/staff/schedule/` | Врачи × дни: график и кабинеты из расписания поликлиники |
| Пациенты `/staff/patients/` | Все записанные и их талоны |
| Статистика `/staff/stats/` | Метрики «до» по выгрузкам поликлиники и экономический эффект |
| Настройки `/staff/settings/` | Проверка сервера и режима МИС, журнал ошибок, очистка талонов |

Кабинета врача нет: по кейсу рабочее место врача — МИС, а ассистент работает с регистратурой.

### Откуда данные

| Экран | Источник |
|---|---|
| Разговор пациента | `POST /api/chat`, голос — `/api/asr`, `/api/tts` |
| Плашка «имитация МИС» / «МИС не подключена» | `GET /api/health` → `mode` (`demo`/`mock` → имитация, `no-stand` → не подключена, `stand` → без плашки) |
| Серые подписи под ответом бота | поля `status` и `source` ответа `/api/chat`; пока их нет — выводятся из `booking`/`escalation`/`options`/`intent` (`shared/domain/replyTags.ts`) |
| Панель регистратора: показатели, журнал звонков | `GET /api/calls` (опрос каждые 5 с) |
| Очередь переводов | `GET /api/handoffs`, `PATCH /api/handoffs/{id}`; кнопка «Регистратор» у пациента просит перевод через `/api/chat` |
| Исходящий обзвон | `GET /api/reminders`, `POST /api/reminders/run`, `POST /api/reminders/{visit_id}/call` |
| Врачи, кабинеты, графики | `GET /api/doctors` (загружается один раз за открытие страницы, `shared/store/doctorDirectory.ts`) |
| Звонок сейчас | `GET /api/live` (опрос раз в 2 с) + демо-звонок с сайта через BroadcastChannel |
| Талоны пациента | браузер (`shared/store/ticketStorage.ts`), собираются из подтверждённых записей `/api/chat` |

Демо-данных нет: пустой сервер — пустые таблицы. Любая ошибка запроса видна цифрой (404, 405, 500…) и пишется в журнал ошибок.

Статусы обзвона и цвета (`shared/domain/reminders.ts`): ожидает — серый, в очереди / звоним — синий с пульсом, подтвердил — зелёный,
перенёс — фиолетовый (+ новое время), отменил — оранжевый, не дозвонились / без ответа — розовый, ошибка звонка — красный. Жёлтого нет.

Цвета разговора: **ИИ Здравушка — синий**, **пациент — серый**, **регистратор — зелёный**.

**Как показать перехват:** откройте `/` и `/staff/live/` в двух окнах одного браузера, начните звонок,
нажмите «Перехватить разговор». Окна связаны через BroadcastChannel; формат — `shared/live/channel.ts`, типы — `shared/types/live.ts`.

Картинки — `public/img`, иконки — `public/img/icons` и `shared/ui/NavIcons.tsx`.

## Устройство кода

Принцип — **одна задача на файл** (S из SOLID). Компонент ≤ 100 строк, любой файл ≤ 150, функция ≤ 60 —
это проверяет линтер. Правила (что показать, какой цвет, когда выдать талон) — чистые функции без React,
их проверяют автотесты.

```
app/            маршруты Next.js — по 1–5 строк, только подключают экран из features/
features/       экраны, каждый в своей папке
  call/           звонок пациента
    CallScreen.tsx  сборка экрана (раскладка + обработчики)
    model/          состояние звонка (useReducer) и что из него показать — без React
    hooks/          сессия /api/chat (useChatSender — номер звонка, опоздавшие ответы отбрасываются),
                    голос (микрофон, озвучка, номер хода), таймер, связь с «Звонком сейчас»
    components/     микрофон, кнопки, лента диалога, поле ввода
    details/        нижняя панель «Что понял Здравушка» / «Запись на приём»
  registrar/      панель регистратора: queue/ очередь, reminders/ обзвон, journal/ журнал
  live/ errors/ settings/ tickets/ patients/ schedule/ stats/
shared/         общее для всех экранов
  config.ts       все технические настройки: адрес сервера, таймауты, частота опроса, ключи хранилища
  api/            запросы к бэкенду: один request() с таймаутом и повторами, журнал ошибок;
                  parse*.ts — проверка формы каждого ответа (не та форма → ошибка 502, а не падение экрана)
  types/          контракт с бэкендом (меняем только вместе с бэкендом)
  domain/         правила предметной области — чистые функции
  store/          талоны в localStorage (маскированные, 30 дней)
  hooks/          опрос сервера, health, всплывашки, кнопки с ожиданием
  ui/             общие компоненты: шапка, меню, бейджи, талон, реплика;
                  ErrorBoundary — вместо «белого экрана» сообщение и кнопка «Обновить»
  browser/        микрофон, плеер, звук, печать, скачивание файла
  live/           BroadcastChannel между окном пациента и «Диалогами»
styles/         CSS по экранам, порядок подключения = порядок каскада (styles/README.md)
tests/          автотесты (vitest): правила, разбор ответов, сеть, хранилище, хуки и гонки в звонке
```

**Как добавить, не ломая остальное (O из SOLID — расширяем таблицей, а не правкой кода):**

| Что | Где одна строка |
|---|---|
| Новый статус обзвона | `RULES` в `shared/domain/reminders.ts` |
| Новый бейдж «что сделано в МИС» | `DONE_IN_MIS` в `shared/domain/replyTags.ts` |
| Новый режим МИС | `VIEW` в `shared/domain/misMode.ts` |
| Новая причина перевода (значок, цвет) | `REASONS` в `features/registrar/queue/handoffView.tsx` |
| Новый участник разговора | `SPEAKERS` в `shared/ui/Bubble.tsx` |
| Пункт меню | `shared/ui/menus.ts` |

Экраны не обращаются к `fetch` напрямую — только через `shared/api/*` (D из SOLID: экран зависит от функции
`getCalls()`, а не от адреса и формата запроса).

## Контракт с бэкендом (FastAPI)

Типы — `shared/types/`. Проверено на актуальном бэкенде (project-main, режимы `mock` и `no-stand`).

| Метод | Путь | Что использует фронт |
|---|---|---|
| GET | `/api/health` | `mode`: `stand` / `mock` / `no-stand` → плашка; `pd_trusted_ai_only` → «Настройки» |
| POST | `/api/chat` | `reply`, `intent`, `collected`, `options`, `booking`, `escalation`, `done`, `status` (`in_progress` / `completed` / `handoff` / `error`), `source` («МИС», «регламент РГ-ТЕЛ-01») |
| POST | `/api/asr`, `/api/tts` | голос |
| GET | `/api/calls` | показатели дня, журнал звонков |
| GET | `/api/live` | идущие телефонные звонки (поля как у `/api/calls` + `active`); `[]` — звонков нет |
| GET | `/api/doctors` | справочник врачей: `id, fullName, specialty, department, patients, cabinet, slotMin, weekly` |
| GET | `/api/handoffs` | очередь переводов |
| PATCH | `/api/handoffs/{id}` | `{ "status": "в работе" \| "перезвонили" \| "закрыта" }` |
| GET | `/api/reminders` | обзвон: `ожидает`, `в очереди`, `звоним`, `подтвердил`, `перенёс`, `отменил`, `не дозвонились`, `без ответа`, `ошибка звонка` |
| POST | `/api/reminders/run` | `{ queued, note? }` |
| POST | `/api/reminders/{visit_id}/call` | позвонить одному пациенту; 404 / 409 / 503 показываются кодом |

Талон создаётся только на завершённом шаге (`status = completed`, запись или перенос); на шаге
«Отменяю запись… Верно?» талон не создаётся.

## Безопасность и надёжность фронта

- Нет секретов и токенов: фронт ходит только в свой бэкенд (`/api/...`), к стенду МИС напрямую не обращается.
- Content-Security-Policy в `app/layout.tsx`: скрипты, стили, картинки и запросы — только со своего адреса;
  `object-src 'none'`, `base-uri 'self'`, `referrer: no-referrer`. Нет `dangerouslySetInnerHTML`, внешних CDN, шрифтов и аналитики.
- Тайм-аут запросов: 35 с для `/api/chat`, 30 с для `/api/asr`, `/api/tts`, 15 с для остальных → код 408 вместо вечного ожидания.
  Таймаут действует и на чтение тела ответа (сервер прислал заголовки и завис).
- Проверка ответов (`shared/api/parse*.ts`): объект вместо списка, `null`, число вместо строки, вложенный объект
  в «Что понял Здравушка» — ошибка 502 «неожиданный формат» или пропуск негодной строки, а не падение экрана.
- Повторы при сбоях (`shared/api/retry.ts`, покрыто тестами):

  | Ответ | Что делает фронт |
  |---|---|
  | 429 | ждёт столько, сколько указал сервер в `Retry-After` (не дольше 10 с), и повторяет |
  | 408, 502, 503, 504, нет сети | повтор через 0,5 с и 1,5 с, потом ошибка кодом |
  | 400, 404, 409, 500 | сразу ошибка кодом и понятная причина (текст от сервера, если он короткий) |

  Повторяются только безопасные запросы: чтение (GET) и распознавание речи. Озвучка не повторяется — пациент не ждёт паузу,
  Здравушка просто отвечает без звука. `POST /api/chat` сам не повторяется — повтор мог бы записать пациента дважды;
  вместо этого у ошибки в чате кнопка «Отправить ещё раз».
- Опрос сервера не наслаивает запросы: пока прошлый не ответил, новый не уходит (медленный сервер не забивает браузер).
- Звонок: «Заново», «Завершить» и перехват регистратором сразу останавливают микрофон и озвучку; ответ сервера или
  распознанная фраза, пришедшие позже, к новому звонку не прилипают. «Регистратор» при недоступном сервере не обещает
  «соединяю» — показывает ошибку и что делать.
- Речь не распознана: первый раз Здравушка просит повторить и слушает дальше; два раза подряд — перестаёт слушать по кругу
  и предлагает написать текстом или нажать «Регистратор». Пациент молчит 30 с — микрофон выключается с подсказкой.
  Микрофон недоступен — своя подсказка: сайт не по https, браузер не умеет, нет разрешения (`features/call/model/speechMisses.ts`).
- Сбой экрана — не белый экран, а сообщение с кнопкой «Обновить» (`shared/ui/ErrorBoundary.tsx`); в кабинете меню остаётся,
  переход на другой раздел сбрасывает ошибку. Испорченные талоны и журнал ошибок в браузере пропускаются.
- Воспроизводимость: точные версии зависимостей в `package.json` + `package-lock.json`, `npm ci`; Node 20–24 (`.nvmrc` — 22).
- Журнал ошибок: одинаковая ошибка пишется не чаще раза в минуту (опрос при упавшем сервере не забивает журнал), до 500 записей.
- Персональные данные в браузере: только талоны пациента; через 30 дней после приёма удаляются сами, есть кнопка «Очистить».
  В очереди переводов ФИО сокращено до инициалов. Ввод в чат ограничен 500 символами.
- Зависимости: `npm audit` — 0 уязвимостей (postcss закреплён на исправленной версии через `overrides`).

Что нужно со стороны сервера (фронт этого сделать не может): вход в `/staff` по учётной записи,
ограничить CORS своим адресом вместо `*`, заголовки `X-Frame-Options`/`frame-ancestors` и HTTPS (микрофон работает только по https).

## Откуда цифры на дашборде

`shared/domain/baseline.ts` — посчитано по выгрузкам: журнал звонков 01.06–31.08.2026 (17 772 звонка) и история записей 25.03–24.09.2026 (35 470 записей).
Формулы экономического эффекта — там же, в функции `economics()`.
